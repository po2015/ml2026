一家企业学院上线了八种语言。内容翻译得很漂亮，课程却没法用：德语里 Submit 按钮溢出了胶囊形状，法语里导航菜单折成了两行，阿拉伯语版本里「下一步」箭头指错了方向，俄语里写着「Question 3 of 10」的进度标签和分数显示撞在了一起。这些都不是翻译错误，而是一个设计假设造成的：认为界面文字是固定长度的。它从来不是。英语是世界上最紧凑的语言之一，任何围绕英语字符串长度设计的课程 UI，都是一颗等着第二语言来引爆的版式地雷。

## 崩坏背后的数字

膨胀系数稳定到足以作为设计依据：

| 语言 | 相对英语的典型膨胀 | 经典重灾区 |
|---|---|---|
| 德语 | +25–35% | 无法优雅断字的复合名词 |
| 法语 | +15–25% | 到处都是冠词和介词 |
| 俄语 | +15–25% | 单词长，UI 术语没有简短同义词 |
| 西班牙语 | +15–25% | 「Next」→「Siguiente」已经算温和的了 |
| 阿拉伯语 | +25% *外加* RTL | 版式整体镜像，字符串同时变长 |
| 中日韩 | −20–40%（更短） | 相反的问题：UI 显得空，点击热区缩水 |

最先崩坏的 UI 区域，按顺序：**按钮**（简短的英语动词变成长短语）、**定宽菜单和标签页**、**标签与数值配对**（「Score: 85」——标签变长，一对就撞车）、**按一行尺寸设计的 toast/弹窗消息**、以及**表格表头**。我们的[文字膨胀通用指南](/zh/news/text-expansion-translation-layout/)讲的是文档侧；课程 UI 更严苛，因为没有流动的页面排版来吸收增长——每个元素都被钉死在像素固定的播放器里。

## 防患于未然的设计规则

- **给每个字符串容器预留 40% 的额外宽度。**如果按钮宽度是按「Submit」定的，德语版上线那天就已经坏了。按最长的预期译文来定按钮尺寸，或者做成自动宽度加合理的 max-width。
- **播放器 UI 里绝不用图片文字。**烘进 PNG 的按钮意味着每种语言都要重做图——和[图表里烘死文字](/zh/news/infographic-chart-localization/)是同一笔税。活文字，否则不上线。
- **把标签和数值拆开。**「Question 3 of 10」做成三个数据驱动的组件（「Question」、3、「of 10」），就能按每种语言的语法重新组装；做成一条硬编码字符串，在语序不同的语言里就会支离破碎——有些语言还需要完全不同的措辞（「10 题中的第 3 题」）。
- **高频重复控件优先用图标加 tooltip**，但关键操作绝不只用图标——图标在不同文化中的歧义本身就是个[本地化问题](/zh/news/image-icon-color-localization/)。
- **阿拉伯语版本要在开工时设计，而不是收尾时补。**RTL 会镜像整个播放器：导航方向、进度条填充方向、「下一步」箭头朝向，详见 [RTL 网页设计](/zh/news/rtl-website-design-arabic/)。给一门已完成的课程 retrofit RTL，成本会超过当初整个 UI 的开发。

## 课件制作工具这一环

现代工具能帮你，前提是用对：

- **Storyline/Rise**：播放器 UI 文字（按钮、消息、菜单标签）集中在 *player text labels*（播放器文本标签）里，作为一个整体导出翻译——参见 [Storyline 工作流](/zh/news/articulate-storyline-translation-workflow/)。翻了幻灯片内容却忘了播放器标签，交出来的就是个双语弗兰肯斯坦：德语幻灯片，英语按钮。
- **自研 HTML5 播放器**：字符串必须放在资源文件里（JSON/properties），绝不内联在代码里，更不能——最糟的情况——混在课程内容里。
- **LMS 的外壳也是 UI**：结课消息、注册邮件、证书模板。它们也会膨胀。

无论用什么工具，验证步骤都一样：**伪本地化（pseudolocalization）**。按照[伪本地化测试指南](/zh/news/pseudolocalization-testing-guide/)，用一个把每条字符串填充 40% 并翻转方向的伪语言环境跑一遍课程——所有溢出、截断和硬编码字符串一遍全部现形，而且这发生在翻译第一个词之前。这是整个本地化预算里最便宜的一道质检。

## 内容侧的缓解手段

有些膨胀问题，在写作环节解决比在排版环节解决更好：

- **源头 UI 文案写短一点。**用「Submit」而不是「Submit your response」；用「Retry」而不是「Try this question again」。源头简洁是最大的杠杆——你砍掉的每个词，都在为全部八种语言省空间。
- **维护一份 UI 术语表。**课程界面反复使用的也就几十条字符串；一致地翻译它们（并选择天然简短的对应说法——这是母语译员的工作，不是词典的）既能防溢出，也能防「一门课程里 Submit 出现三种译法」的问题。
- **数字和格式保持 locale 正确**，分数、日期、时长都一样——[格式规范](/zh/news/date-currency-format-localization/)在课程内部和在网站上同样适用。

## 上线前检查清单

1. 所有播放器字符串已外置，并纳入翻译包
2. 每个字符串容器都按 +40% 宽度测试过（伪语言环境跑一遍）
3. 标签与数值分离；代码里没有烘死的语法
4. 播放器的 RTL 变体经过实际验证，而不是想当然
5. 按钮、菜单、弹窗、表头都在*最长的*语言（通常是德语）下做过目视质检
6. 证书和 LMS 消息检查过——学员也会看到这些

课程 UI 是培训内容外面的画框；学员能原谅一句别扭的话，但一个读不了、点不着的按钮，会带走整个项目为之存在的完课率。我们的[电子学习本地化团队](/zh/services/localization/elearning/)把膨胀与 RTL 审计作为标准项目步骤——在翻译开始之前，而不是在它崩坏之后。[把课程发给我们](/zh/contact/)，我们来跑伪语言环境审计。
