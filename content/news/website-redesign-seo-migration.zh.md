改版看起来很漂亮。外贸经理签了字，新网站在周五上线，到下一个周五，询盘停了。那个靠「hydraulic cylinder manufacturer」排了三年的页面——承担了全部询盘三分之一的那一个——现在 404 了，因为新 URL 结构用的是 `/products/hydraulic-cylinders/`，而没有人映射旧 slug。测试站的 `noindex` 标签跟着上了生产环境，Google 正在主动把新页面从索引里*移除*。还有那些带着行业目录外链的旧博客文章？改版时被删了，因为「没人看那些」。三年攒下的排名，一周就没了——而且只有发现得够快才完全救得回来。这是防止这一切的清单。

## 为什么改版会毁掉排名（以及为什么不必如此）

Google 排名的是 *URL*，不是网站。你网站持有的每一个排名都绑在一个具体地址、一个具体页面的内容和指向它的链接上。一个改 URL 却不做重定向、重写正在起量的内容、或弄断技术信号（hreflang、canonical、sitemap）的改版——从 Google 的视角看——根本不是改版。那是一个恰好共用你域名的、不受信任的新网站。恢复不会自动发生，也不会快：你要像[全新网站在头 90 天那样](/zh/news/new-export-website-seo-90-days/)，一个页面一个页面地重建信任。

好消息是：每一种失败模式都是已知的，每一种都有对策。迁移失败是因为跳了步骤，不是因为运气差。

## 第一阶段：动手之前——迁移前审计

整个项目里最重要的一份文件是 **URL 清单**。在任何设计工作开始之前，抓取现有网站（Screaming Frog，或你的 CMS 导出），把三个数据源合进一张表：

1. **网站上的每一个 URL**，附上它当前的 title 和 H1。
2. **每一个有流量的 URL**——来自 [Search Console](/zh/news/google-search-console-exporters/)，每个页面 12 个月的点击和展示。
3. **每一个有外链的 URL**——来自 Search Console 的链接报告或你常用的外链工具。

任何出现在清单 2 或清单 3 里的 URL 都是承重墙。它要么在原 URL 上原样活下来，要么拿到一个指向最接近等价页的 301 重定向。没有第三种选择。「没人看那些博客文章」是一个要由数据投票的主张——一篇每月 40 次点击、带着三条目录外链的文章，是在自食其力的。

既然已经进了 Search Console，顺便导出每个页面的头部查询。它们告诉你每个排名页面*为什么*能排——这正是你要保住它所需的信息。

## 第二阶段：URL 映射与 301 重定向计划

重定向映射表是迁移的心脏。每个旧 URL 占一行：

| 旧 URL | 在新站的状态 | 动作 |
|---|---|---|
| `/hydraulic-cylinder.html` | 以 `/products/hydraulic-cylinders/` 存在 | 301 → 新 URL |
| `/about-us.html` | 路径不变 | 无需处理 |
| `/news/2019-fair-report.html` | 下线，无等价页 | 301 → 最近的父级（`/news/`） |
| `/products/discontinued-line.html` | 下线，有替代产品 | 301 → 替代产品 |

让这一步不出错的规则：

- **重定向到最接近的等价页，绝不一锅端指向首页。** 五百条重定向指向 `/`，是在告诉 Google 五百页内容消失了。它会把它们当成软 404，链接权重随之蒸发。
- **最多一跳。** 旧 URL → 新 URL 直达。重定向链（A → B → C）每一跳都在漏权重，还拖慢爬虫。如果旧站本身已有重定向，把它们更新为指向最终目的地。
- **重定向永久保留——至少保留几年。** 从[阿里国际站店铺迁到独立站](/zh/news/alibaba-to-owned-website-migration/)的出口商在域名上学过这一课：保留一条重定向的成本是零；过早删除它的成本是丢掉每一条仍指向旧地址的外链。
- **能不改 URL 就不改。** 最好的迁移让每一个有排名的 URL 保持原样。改版的是页面，留下的是地址。任何平台或代理商以「系统就是这样」为由强制改 URL，都要坚决顶回去。

## 第三阶段：保住正在排名的内容

设计团队做改版；SEO 死在改写里。那个靠「dn50 stainless ball valve」排名的页面，能排是因为它具体的内容——规格表、压力等级、页面回答的那个问题短语。为了更干净的版式把这些剥掉，排名跟着一起走。

对 URL 清单里每一个有流量或有外链的页面：

- **先把排名内容逐字搬过去，再谈改进。** 规格、表格、认证、买家搜索的长尾措辞。等迁移稳定之后再编辑，不要在迁移过程中改。
- **排名页面的 title 和 H1 保持稳定。** 你可以在一个不动的标题周围做现代化设计。把「Stainless Steel Ball Valves — DN15–DN300, ATEX Certified」改写成「Flow Solutions for Industry」，等于删除一个排名。
- **注意[多语言版本](/zh/news/multilingual-content-sync-maintenance/)。** 一个排名页面的每个语言版本都是独立排名的。德语页面的内容需要和英文页面同等的保全纪律——而且每种语言有自己的[关键词版图](/zh/news/multilingual-keyword-research-guide/)，所以译文内容要继续对准那个市场里真正在排名的词。

## 第四阶段：技术层接管——hreflang、canonical 与测试站陷阱

技术层是迁移最常无声翻车的地方，因为什么都*看起来*没坏：

- **Hreflang 必须完整且对称地重建。** 如果你的英文、西语、俄语页面今天互相引用，新站必须用新 URL 复刻完全相同的关系——每个页面指向所有兄弟页面和它自己，回链完整。迁移期间，[常见的 hreflang 失败模式](/zh/news/hreflang-mistakes-multilingual-b2b/)会成倍放大：少一条回链，Google 就开始给错误的市场投放错误的语言版本——你的德语页面就是这么在英文查询上反超英文页面的。
- **Canonical、结构化数据和 XML sitemap** 用新 URL 重新生成并在上线时重新提交。检查 [schema 标记](/zh/news/schema-markup-manufacturer-websites/)里有没有写死的旧 URL。
- **测试站 `noindex` 陷阱。** 测试站正确地设置了 `noindex`，通常还在 `robots.txt` 里屏蔽。这两个设置经常跟着上线到生产环境。网站在浏览器里看起来完美无缺，同时在叫 Google 删除每一个页面。这是最常见的上线灾难，代价是真金白银：等到有人发现询盘停了，往往已经被取消索引好几周。
- **性能也是迁移的一部分。** 新主题带着更重的 JavaScript、没优化的首屏大图和旧站没有的第三方脚本。在测试站上[从你的实际出口市场测 Core Web Vitals](/zh/news/core-web-vitals-b2b-exporters/)——一个让圣保罗加载时间翻倍的改版，是在用排名换美观。

## 第五阶段：上线当天检查

DNS 切换的那一刻，按顺序跑这张清单：

1. **关掉 noindex，放开 robots.txt。** 查看首页和三个深层页面的源代码：没有 `noindex` meta，robots.txt 允许抓取。这件事先于一切。
2. **重定向抽查。** 从清单里抽二十个旧 URL——流量最高的那些——确认每一个都一跳落到正确的新页面，状态码 301，不是 302。
3. **在 Search Console 提交新 sitemap**；移除旧 sitemap。
4. **Hreflang 双向验证**，抽样若干语言对。
5. **联系表单和 RFQ 表单能用**——上线周坏掉的表单在流量数据里看不见，只表现为一片寂静。
6. **统计代码在新模板上正常触发**，转化事件完好。

## 第六阶段：上线后监控与恢复时间线

头两个月每周看 Search Console——把[出口商的 Search Console 例行检查](/zh/news/google-search-console-exporters/)加密执行：

- **覆盖率报告**：404 飙升说明有漏掉的重定向；新页面出现「已抓取——尚未编入索引」在头几周是正常的。
- **效果报告，页面维度**：把头部 20 个页面和迁移前的基线对比。重定向过的页面预期下跌 10–30%——这是 URL 变更期间 Google 重新评估的正常代价。
- **hreflang 国家里出现错误语言的展示**：这是 hreflang 重建有漏洞的危险信号。

恢复要多久？诚实的数字：URL 和内容都没动的页面应该晃 2–4 周后回到基线。重定向过的页面通常要 4–8 周，竞争激烈的词有时要一个季度。被大幅改写的内容是一次重新排名事件——按新内容的时间线对待。一个页面 90 天还没恢复，就不会自己恢复了：重新检查重定向目标的相关性、内容匹配度和指向它的内链。这个诊断直接接入后续的 [SEO 衡量与 ROI 链条](/zh/news/seo-roi-b2b-export/)。

## 极简版

改版前先导出你的 URL。每一个重要的都做重定向。排名内容和标题原样保留。hreflang 完整重建。上线时移除 `noindex`——然后再查一遍。监控两个月，每周一次。六行，而你听过的每一个改版灾难故事，都能追溯到其中被跳过的一行。
