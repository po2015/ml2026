一位市场经理收到某条产品视频的成品字幕：十二种语言，全部以 `.srt` 文件交付。网站团队的播放器拒收——它要 WebVTT。有人把扩展名一改，结果一半的视频播放时完全没有字幕。与此同时，阿拉伯语文件在记事本里打开是一团颠倒的乱码，日语文件该出字的地方全是问号。这些没有一样是稀奇事：字幕文件就是带时间戳的纯文本，但这份简单底下恰好藏着那些决定你的[多语言字幕](/zh/news/subtitle-translation-best-practices/)能不能真正播放的细节——格式能力、编码、文字方向。这是三种你会遇到的格式及其间陷阱的实战指南。

## SRT：万能老黄牛

SubRip（`.srt`）是最古老、兼容性最好的格式：一个序号、一行时间戳、正文、一个空行——仅此而已。

```srt
1
00:00:02,500 --> 00:00:05,000
The PVG-32 valve handles flows up to 130 l/min.

2
00:00:05,200 --> 00:00:08,400
Commissioning takes under ten minutes.
```

时间戳格式为 `hours:minutes:seconds,milliseconds`——注意那个**逗号**。SRT 几乎不支持任何样式（少数播放器认得基本的 `<i>`/`<b>`/`<u>` 标签，很多不认）、不支持定位、不支持元数据。这个局限正是它的力量：地球上每一个剪辑软件、播放器、平台和 CAT 工具都读得懂 SRT。把它用作你的**翻译交换格式**——发给译者、收回来的都是它——以及用于接受它的平台（YouTube、LinkedIn 和大多数社交平台都接受）。

## WebVTT：Web 标准

WebVTT（`.vtt`）是 HTML5 `<track>` 元素和大多数网页播放器所要求的格式。它看起来像加了头部、又有几处关键差别的 SRT：

```vtt
WEBVTT

00:02.500 --> 00:05.000
The PVG-32 valve handles flows up to 130 l/min.

NOTE
Reviewed by native speaker, 2027-04-10

00:05.200 --> 00:08.400
Commissioning takes under ten minutes.
```

- 文件**必须以 `WEBVTT` 开头**——没有头部的改名 SRT 是非法的 VTT，这就是改后缀名这招失灵的原因。
- 时间戳的毫秒用**句点**（`00:02.500`），小时位可以省略。
- 它支持 **cue 设置**（位置、对齐、换行）、**说话人标签**（`<v Anna>`）、**注释**（`NOTE` 块），以及通过页面样式表中的 `::cue` 做 CSS 样式。

任何嵌入你自己网站的内容，以及 e-learning 平台（[LMS 播放器](/zh/news/multilingual-lms-deployment/)绝大多数要求 VTT），都用 VTT。务实的流水线是：在 SRT 里翻译（工具兼容性最好），再为 Web 交付转成 VTT——用真正的转换器，不是改名。

## ASS/SSA：当样式本身就是目的

Advanced SubStation Alpha（`.ass`）是样式化字幕的格式：逐条字幕的字体、字号、颜色、描边、阴影、精确的屏幕定位，甚至动画。当字幕必须*看起来经过设计*时你就会遇到它——动漫和字幕组文化造就了它，但它同样适用于把品牌化、带定位的字幕烧录进营销视频，或者把中文文字摆在不遮挡下三分之一演示 UI 的位置。

代价是复杂度和兼容性。ASS 携带完整的样式区和事件列表；网页播放器基本不认它，译者也很容易弄坏它的覆盖标签（`{\an8}`、`{\pos(320,40)}`）。把 ASS 当作**成品格式**：翻译在 SRT/VTT 里进行，然后由字幕师在 ASS 里重建样式用于烧录，烧录后的视频才是交付物。当字幕是[烧录进画面而非作为文件交付](/zh/news/burned-in-subtitles-vs-caption-files/)时，ASS 属于烧录那一支。

## 真正毁掉交付的陷阱

1. **编码：UTF-8，带不带 BOM 皆可，其他一律不行。** SRT 没有编码声明；存成 Latin-1 或 GB2312 的文件会让日文和阿拉伯文变成乱码。交付和要求都认准 **UTF-8**。BOM 有助于 Windows 工具正确识别编码；大多数现代播放器都能接受。
2. **阿拉伯语和希伯来语的文字方向。** 字幕*文件*是逻辑顺序存储的；由*播放器*负责双向文本渲染。混合方向的行——一句阿拉伯语里夹着你的拉丁字母产品名——如果标点落在行边缘就会渲染错误。阿拉伯语字幕要在真实的目标播放器里测试，而不是在文本编辑器里，并且优先选用双向文本支持完善的播放器。
3. **行长和阅读速度很难扛过翻译。** 德语比英语长约 30%；两行的英文字幕可能变成四行德语，观众在画面停留时间内根本读不完。[文本膨胀](/zh/news/subtitle-text-expansion-contraction/)的规划发生在翻译阶段，而*格式*层面的检查就是字幕 QA 那一关：每行字符数、每条字幕行数、最短显示时长。
4. **剪辑之后的时间轴漂移。** 如果视频在字幕完成后重新剪辑，每条字幕都会错位。字幕文件引用的是绝对时间码——任何剪辑都会使其失效。做字幕前先锁定画面，或者为重同步留一笔预算。
5. **转换时的换行处理。** SRT→VTT 转换器偶尔会把多行字幕弄乱，或丢掉空行分隔符；上传前抽查转换后的文件。

## 务实建议

- **每种语言一份 SRT 母版、UTF-8 编码**，与视频一起归档——它是未来剪辑和平台转换的真相来源。
- **按目的地转换**：自己的网站和 LMS 用 VTT，YouTube／社交平台用 SRT，设计感营销物料走 ASS→烧录。转换是机械性的、可脚本化的。
- **在供应商任务书里写明格式**（「交付 SRT UTF-8 + VTT」），而不是等交付后才发现播放器的要求——这与在[本地化任务书里写清交付物](/zh/news/localization-vendor-brief-template/)是同一条纪律。
- **让 CJK 字幕行数保持简短**：中／日／韩文单位字符信息量更大，翻译后的字幕往往变短——这正是提升阅读舒适度的机会，详见 [CJK 字幕注意事项](/zh/news/chinese-video-subtitling-guide/)。
