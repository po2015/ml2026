「周五之前就能让你的网站变成五种语言——不需要开发。」这是翻译代理（translation proxy）的推销话术，技术上也是真的：把 DNS 指向代理，它抓取你的英文页面，实时机器翻译，然后在语言子域名下输出本地化版本。面对展会死线或市场测试，这种速度是真的。但把代理当作永久架构的出口商会发现，成本在后面才到——在 SEO 里，在文案质量里，在一张永远不结束的月账单里。下面是坦诚的对比：什么时候哪种方案是对的，以及如何在两者之间迁移。

## 两种架构实际怎么工作

**翻译代理**（例如 Weglot 这一类服务，以及服务端代理变体）：代理位于访客和你的源站服务器之间。它爬取你的英文 HTML，把译文存在自己的数据库里，在请求时通过字符串替换输出本地化页面。你的 CMS 永远不知道其他语言存在。

**CMS 原生多语言**：语言版本是你技术栈里的真实内容——WordPress/Polylang 里的翻译页面、Hugo 内容树（本站的模式：一套共享内容结构下的按语言文件）、或带 locale 字段的 headless CMS。翻译发生在*内容工作流里*，每个语言版本都是你的服务器直接渲染的一等公民页面。

## 真正重要的对比

| 维度 | 翻译代理 | CMS 原生 |
|---|---|---|
| **上线时间** | 数天——这确实是它的杀手锏 | 数周（架构 + 翻译） |
| **文案质量掌控** | 机翻产出 + 可在他们的编辑器里译后编辑；你的译员在*他们的*工具里干活 | 你的译员、你的工具、你的[翻译记忆库](/zh/news/translation-memory-dtp-efficiency/)——质量完全归你 |
| **SEO** | 能用但有保留：经 JS 替换输出的内容可能索引不稳定；hreflang 由代理代管；一旦离开你什么都不剩 | 完全掌控：[hreflang](/zh/news/hreflang-mistakes-multilingual-b2b/)、本地化 URL/slug、分市场元数据、干净可爬的 HTML |
| **品牌声音与术语** | 有术语表支持但很粗糙；产品术语漂移很常见 | 术语表强制的翻译，关键处母语撰稿（[日本](/zh/news/japanese-b2b-website-trust/)、[德国](/zh/news/german-market-b2b-buyer-expectations/)） |
| **分市场设计** | 一套版式换文字——RTL、文字膨胀、市场专属页面都是硬仗 | 每个市场可以有自己的页面、版式调整，[RTL 做得地道](/zh/news/rtl-website-design-arabic/) |
| **网站之外的内容** | 只翻译它代理的东西——管不到你的 PDF、邮件或结构化数据 | 翻译资产归你；可在[数据表、邮件、文档](/zh/news/pdf-translation-workflow-editable/)里复用 |
| **数据所有权与退出成本** | 译文存在供应商数据库里；取消订阅，语言版本隔夜消失 | 你的内容，在你的仓库/数据库里，永远 |
| **成本形态** | 每月 50–500+ 美元，*永远*，随字数/语言数上涨 | 前期较高，之后只有新增/变更内容花钱——修订还会因 TM 越改*越便宜* |

## 什么时候代理是正确答案

- **市场验证**：「德语版会带来询盘吗？」这个问题值得用一个每月 99 美元的实验来回答，然后再谈 1 万美元的建设。代理跑一个季度，看数据，再决定。
- **硬死线**：展会就在三周后，必须有东西存在。（不过对展会来说，一个[专门的落地页](/zh/news/trade-show-landing-pages-manufacturers/)通常是更好的快答案。）
- **低风险的量大内容**：支持知识库或博客归档，机翻加轻审的质量可以接受，SEO 价值次要。

注意到规律了吗：代理的闪光点是作为*战术性、可逆*的工具。失败模式是组织性的，不是技术性的——一个周五下午的实验悄悄变成永久架构，两年后你付着企业级价格，输出你不拥有的机器翻译，同时纳闷为什么德语页面不转化。

## 什么时候 CMS 原生是唯一真答案

- **SEO 是你在投入的渠道。**[工业长尾](/zh/news/industrial-long-tail-keywords/)领域的自然搜索，奖励的恰恰是代理做得最差的东西：每种语言独特的、规格丰富的、母语写就的页面，配干净的 HTML。
- **品牌声音重要。**首页、头部产品页、任何高管会念出声的东西——这些值得 transcreation（创译），而代理工作流让创译很别扭。
- **受监管或技术性内容。**当一条翻错的规格就是法律责任时，你需要自己的译员和自己的质检——[MTPE 规范](/zh/news/what-is-mtpe-post-editing/)在你掌控下执行，而不是供应商的黑箱。
- **你在建设一项耐久资产。**每个翻译到位的页面、术语表和 TM 句段都在复利。代理支出不复利任何东西。

## 迁移路径（代理 → 原生）

如果你现在在用代理，季度账单开始让你心里发毛，退出是有序的：

1. **导出你的译文。**大多数代理允许导出它们的 TM/字符串——在取消任何东西之前先做这一步；这是*你的*内容种子。
2. **复用前先审质量。**代理译文基于机翻；让你的供应商或母语审校分级：干净的复用，不行的重翻。通常 60–80% 经审校可以挽救——直接成为新站建设的初始 TM。
3. **搭建原生结构**（也就是把[网站本地化工作流](/zh/news/website-localization-workflow/)做对）：语言树、hreflang、本地化元数据。
4. **带重定向切换**：把代理子域名 URL 映射到新结构，让积累下来的 SEO 价值转移过去。

## 一句话决策

代理 = 租译文，本周上线，什么都不拥有。原生 = 建资产，正经上线，一切留下。用前者验证；用后者建设；永远别把租来的当成房子。
