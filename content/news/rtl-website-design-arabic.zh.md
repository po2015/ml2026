此时此刻，世界的某个角落，一位利雅得的买家正在看一个「阿拉伯语」网站：文字确实是阿拉伯语，但其他一切都是错的——菜单从左侧弹出，面包屑导航读序颠倒，进度条从左往右填充，一个电话号码的数字被双向文本 bug 搅得七零八落。这家公司为翻译付了钱，却跳过了方向。RTL 设计不是翻译任务，也不纯粹是开发任务——它是一门布局纪律，做对与做错，就是一个本地化网站和一个镜像出来的事后补作业之间的差别。

## 哪些要镜像——哪些不要

经验法则：**凡是暗示阅读方向或进程方向的东西都要翻转；凡是代表现实世界物体或标准惯例的东西都不要翻。**

RTL 中要镜像的：

- 页面布局网格：导航、侧边栏、内容分栏
- 文本对齐（默认靠右）、缩进、项目符号位置
- 面包屑、进度指示器、分步向导、时间线
- 暗示顺序的箭头（→ 变成 ←）、轮播方向
- 暗示运动或阅读顺序的图标：前进/后退尖括号、「发送」纸飞机、阅读进度条
- 表单布局：标签和输入框从右往左排列

**不**镜像的：

- Logo（永远别翻转文字商标）
- 代表物体的图标：电话、信封、打印机、时钟（不过钟*表盘*保持不变——时间不会倒流）
- 媒体控制：播放（▶）、快进、音量——通用惯例让它们保持 LTR
- 图表：在科学惯例中，x 轴依然从左向右递增——但*标签和图例的布局*遵循 RTL，这一点我们在[图表本地化](/zh/news/infographic-chart-localization/)一文中讲过
- 数字、电话号码、拉丁数字的日期：它们在 RTL 流中*内部*保持 LTR（bidi bug 就藏在这里——详见下文）

## 双向文本问题

最棘手的 bug 不在布局——而在**混合方向的字符串**。阿拉伯语文本按 RTL 流动，但数字、拉丁字母品牌名、URL 和技术术语保持 LTR。当两者出现在同一字符串里，Unicode 双向算法决定视觉顺序——而它经常决定错：

- 一个以型号结尾的句子，可能把型号渲染到错误的一端
- 带 `+` 前缀的电话号码可能被打乱（`+966 11 234 5678` 显示成 `5678 234 11 966+`）
- 紧邻拉丁文本的标点会跳到错误的一侧

修复手段在标记里：把内嵌的拉丁片段包进 `<bdi>`，或应用 `unicode-bidi: isolate`；必要时在标点周围使用方向控制符（`&lrm;`）；并且*用真实内容测试*——这和[阿拉伯语 DTP](/zh/news/arabic-dtp-indesign-rtl/) 是同一套纪律，印刷品里适用的是完全相同的 bidi 规则。正如我们在[阿拉伯语 SEO](/zh/news/arabic-seo-gulf-markets/) 中指出的：LTR 渲染坏掉的阿语页面，Google 照排不误——但买家不会在上面下单。

## 用一套代码库服务两个方向

现代 CSS 让双方向网站可以维护——前提是你从一开始就用逻辑属性来写：

| 物理属性（RTL 下会坏） | 逻辑属性（自动适配） |
|---|---|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left: 20px` | `padding-inline-start: 20px` |
| `left: 0` / `right: 0` | `inset-inline-start: 0` / `inset-inline-end: 0` |
| `text-align: left` | `text-align: start` |
| `border-right` | `border-inline-end` |

在阿拉伯语页面的 `<html>` 元素上设置 `dir="rtl"`（我们的模板会根据语言配置自动完成），用逻辑属性书写样式，布局就会自动镜像。仍需手工处理的：翻转方向性图标（提供 RTL 变体，或对特定暗示方向的图标使用 `transform: scaleX(-1)`——绝不要对整个组件用），以及逐项核对上面那份例外清单。

## 字体排印与设计细节

- **字体**：阿拉伯语需要专门打造的阿语网页字体（而不是拉丁字体加阿语回退）。行高需要比拉丁文设置增加约 20–30%——阿语的变音符号和字形在拉丁行高下会相互碰撞。这与 [CJK-拉丁字体搭配](/zh/news/cjk-latin-font-pairing/)是平行的纪律，只是具体参数不同。
- **数字**：海湾商务场合压倒性地使用西方数字（0-9），而非阿拉伯-印度数字（٠-٩）——但要*了解你的市场*；某些与政府相关的内容预期使用阿拉伯-印度数字。按市场选择并保持一致，正如[日期与数字格式](/zh/news/date-currency-format-localization/)的原则一样。
- **粗体与斜体**：阿拉伯语没有真正的斜体；合成倾斜看起来是坏的。强调用字重和颜色，不要用倾斜。
- **字距（letter-spacing）**：绝不要对阿拉伯语使用——它会打断字母之间的连写。CSS 里任何全局 `letter-spacing` 都必须对阿拉伯语重置。

## 上线前审计清单

发布阿拉伯语板块之前：

1. 完整镜像布局：导航、页脚、面包屑、表单、轮播
2. 方向性图标已翻转；物体图标和 Logo 原样不动
3. bidi 审计：真实内容中的电话号码、邮箱、型号、价格
4. 阿语字体已加载且排在字体栈首位；行高已加大
5. 阿语文本上没有 letter-spacing 或合成斜体
6. 表单：RTL 布局，但邮箱/电话/URL 输入框保持 LTR 输入行为
7. 在一台中端 Android 机上完整点一遍——这是该市场主导的设备档次
